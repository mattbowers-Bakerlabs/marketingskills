# BML Service Offers

How to build an offer for a Baker Labs (BML) client: a local or regional service business, a clinical practice, a professional firm or a multi-location brand. Read it with `bml/context-rules.md` and the **BML: build the offer from rows** table in SKILL.md. Every example here uses placeholders (`<service>`, `<n>`, `<town>`). Fill them only from the client's rows; where a row is missing, write `[NEEDS PROOF: <row ID>]`.

---

## 1. Start with what's on file

Before designing anything, list what the record already holds. Most local-service offers already exist in scattered form (a warranty, a free estimate, a financing partner, a spring promotion). The job is usually to assemble and name them, not invent new ones.

| Ask | Rows |
|---|---|
| What do they sell, which services matter most? | D-1, D-2, B-5 (want more / less of) |
| How does a job or visit actually run? | D-3 |
| What can be published about price? | D-4, E-10 |
| What do they already promise? | D-5 |
| What makes buyers hesitate, and what reduces it? | D-6, F-8, F-9, G-7, I-4 |
| What packages, plans, financing or entry offers exist? | D-7 |
| What do they upsell? | D-8 |
| What's coming up seasonally? | D-11, I-10 |
| How much more work can they take? | B-6 |
| How fast are leads answered, and how can people book? | I-3, I-9 |
| What do competitors offer? | L-6, E-1, E-8 |
| What may never be said? | J-2, J-3, J-4, F-13, H-5 |

If B-6 says they're at capacity, or B-5 says they want less of a service, note it beside that service in the recommendation and flag it in the footer; don't drop the service for it.

## 2. Formats by segment

### Home services and construction (remodelers, kitchens, carpentry, trades)

| Component | Default | Rows |
|---|---|---|
| Core | A named project path for one priority service: consult → design → build → walkthrough, as D-3 describes it | D-1, D-2, D-3 |
| Bonuses | Things that close D-6 doubts and the client already does: design consult, written scope, material samples, a project timeline, a post-job check | D-6, D-8, D-10 |
| Guarantee | The warranty in D-5, stated exactly (workmanship years, materials, manufacturer). Nothing stronger without client approval | D-5, J-3 |
| Scarcity | Real schedule: "booking <season> projects now", "<n> start dates left for <month>" only from B-6 and I-10, confirmed before publishing | B-6, I-10, D-11 |
| Name | Outcome- or process-named in the client's voice, for example "The <client> <service> Plan" | 01, E-6, H-5 |
| Price | Ranges or "projects typically start at" only from D-4. Financing only as D-7 states it | D-4, D-7, E-10 |

Watch: license details where J-3 requires; project photos only with a release (J-6); never AI images presented as real projects; service area from B-8.

### Clinical practices (medical, dental, eye care, imaging, regenerative)

The offer is **reassurance and access**, not a deal.

| Component | Default | Rows |
|---|---|---|
| Core | The visit or service path as D-3 describes it: what happens at the first visit, who you see, what comes next | D-1, D-2, D-3 |
| Bonuses | Access and clarity, not gifts: what's included in the first visit, insurance and payment clarity, online booking, hours | D-6, D-7, I-9 |
| Guarantee | None about outcomes. Service promises only if D-5 holds them | D-5, J-2, J-3 |
| Scarcity / urgency | None, unless a page 12 row permits it. No countdowns, "limited openings" or fear framing | §7, page 12 |
| Name | Plain and descriptive ("New patient visit", "<service> consultation") | 01, H-5 |
| Price | Self-pay prices, packages or memberships only from D-4 and D-7. Clinical claims only from approved published copy, reviewed by a named provider | D-4, D-7, J-3 |

Flag for a person, don't design: free or discounted services for new patients, gifts, referral rewards, and any financing for care. These can be regulatory questions (J-3). Only a J-3 row that explicitly permits one lets you design it, and it still goes to the client's compliance contact.

### Professional services and real estate (law, accounting, financial, agents)

| Component | Default | Rows |
|---|---|---|
| Core | A defined engagement: what's included, who does it, how long, as D-2 and D-3 state | D-2, D-3 |
| Bonuses | Process aids: a first-meeting checklist, a written scope, a fixed-fee option if D-7 holds one | D-6, D-7 |
| Guarantee | Service-level only (response time from I-3, fixed fee, scope). **No outcome guarantees** (case results, returns, savings, sale prices) unless a row permits them | D-5, I-3, J-3 |
| Scarcity | Real deadlines only (a filing date, a season in I-10) | I-10, D-11 |
| Name | Descriptive, credential-appropriate | 01, J-3 |
| Price | Fee structure only as D-4 approves. Required disclosures per J-3 | D-4, J-3 |

### Multi-location brands

Build the offer from the parent brand's rows, then each location's own rows. A promotion, price or capacity line is per location unless the parent's rows say it's brand-wide. Franchisor rules (J-3) apply everywhere. Never put one location's offer, hours or providers on another's page.

### Other (B2B, product companies)

Use the upstream formats in [offer-formats.md](offer-formats.md) that fit, with every component still sourced from rows.

## 3. Upstream tactics, BML treatment

| Upstream tactic | BML treatment |
|---|---|
| Value stack with stated dollar values | Stack bonuses that close D-6 doubts. Show a dollar value only if the client supplied it and D-4 approves publishing it. Never total "you get $<n> of value" from estimates |
| "Only <n> spots left" | Only from a B-6 capacity figure the client confirms is current. "⚠ confirm before publishing". Clinical: not without a page 12 row |
| Countdown timer | Only to a real end date in D-11, removed when it ends. Adding it to a site is publishing: approval first. Clinical: not without a page 12 row |
| Better-than-money-back, double guarantee, pay-after-results | Not proposed for clinical or professional services. For others, a recommendation only, with a refund-risk note for the client |
| Comparison guarantee ("beat <competitor>") | Blocked if J-4 bars naming competitors; otherwise a recommendation only |
| Founding-member pricing, price-increase dates | Only if the client commits to the date and price in writing (D-4, D-11) |
| Bonus expiry | Only if the client will actually remove the bonus on the date |
| Free trial, coupon, annual prepay | Software patterns. Local equivalents: free estimate or consult (if D-3 or D-7 holds it), seasonal promotion (D-11), maintenance plan (D-7) |
| Discount to win new customers | The client's call. Present the trade-off and an offer-based alternative; don't block a D-11 promotion |
| Payment plans and financing | Only as D-7 states them. No rates, terms, approval odds or "no credit check" unless D-7 holds them. Lending and financing wording goes to a person for disclosure review |
| Case studies with names and numbers | G-3 stories and G-2 numbers only; testimonials verbatim from G-5 with permission. Otherwise `[NEEDS PROOF: G-3]` |

## 4. Offer recommendation (agency artifact, Baker house style)

Drafted in the session's outputs folder as `<CODE>_Offer_<service>_YY.MM.DD`; filed to `OUTPUTS/WEBSITE` with a ClickUp record tagged `strategy` when the user asks (see **BML: outputs, approvals and footer** in SKILL.md).

```markdown
# Offer recommendation — [CODE] — <service> — <YYYY-MM-DD>

## Current offer (from rows)
| Component | On file | Row | Status |
...

## Diagnosis
Value-equation scores (agency judgement) with the row behind each. Binding constraint: <lever>.

## Recommended offer
| Component | Recommendation | Rests on | New or on file |
...

## Needs client approval (J-1: <approver>, <turnaround>)
- New guarantee wording: ...
- Prices or ranges to publish (D-4): ...
- Financing or payment wording (D-7), for disclosure review: ...
- Scarcity counts and dates (B-6, I-10, D-11): ...

## Options not recommended, and why
## Gaps to fill: [NEEDS PROOF: ...]
## Context tasks to draft (§8), if approved
<§9 context footer>
```

## 5. Offer copy (client deliverable, client voice)

Written only from approved components. Drafted in the session's outputs folder; filed to `OUTPUTS/WEBSITE` (offer page or section, tagged `website`) or `OUTPUTS/EMAIL` (offer email, tagged `email`) when the user asks.

```markdown
<Offer name>
<One-line outcome for <ICP> in <town / service area>>
What's included: <from D-2, D-3>
Our promise: <D-5 wording, verbatim>
Why <client>: <F row belief> · <G row proof>
<Price line from D-4, or omit> · <Financing line from D-7, or omit>
<Real constraint from B-6 / I-10 / D-11, or omit> ⚠ confirm before publishing
<CTA in 01's required language — call / book / request an estimate per I-9>
<internal, strip before sending: Approver: account lead → <J-1> · §9 context footer>
```

Leave a line out rather than fill it without a row.
